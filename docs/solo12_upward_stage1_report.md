# Solo12 Upward 阶段最终报告

## 最终结论

- 最终 checkpoint：`test_solo12_v3_1/Aug15_14-04-51_latency_endpoint_curriculum40_from8550_2000/model_10550.pt`。
- 最终控制：`Kp=16`、`Kd=0.5`、`action_scale=0.25`、EMA 动作滤波 8 Hz、策略周期 20 ms。
- 训练最终覆盖 0–40 ms 观测延迟；COM 暂时接受 `xyz ±0.02 m`，其余物理随机化保持 Go2 等级。
- 修正后的同协议测试中，Solo 在固定 20/30/40 ms 下均超过当前 Go2 对照，但 40 ms 严格稳定率仍只有 53.91%，不能表述为高可靠部署已经完成。

## Solo 模型适配

这些差异是机器人模型本身导致的，Upward 和 Forward 共用：

1. **关节与足端语义顺序**：策略统一使用 `FL, FR, RL, RR` 语义顺序，通过名字建立策略顺序与 URDF/Isaac Gym 原生顺序的双向映射。观测、动作、默认关节位置、IK 和关节保护全部使用同一映射。原因是 Solo 与 Go2 的 URDF 关节排列不同，直接按 tensor 下标复用会把腿和关节动作发错。
2. **IMU 安装**：Solo IMU 相对 `Body` 的安装位置为 `[-0.063487, -0.031976, -0.011172] m`，姿态为 `[0, π/2, π]`。启动时校验 URDF 安装关系；策略仍接收 base-frame 量，部署端需要把实机 IMU 数据按该安装变换转到 base frame。原因是 Solo 与 Go2 的 IMU 安装位置和朝向不同。
3. **初始姿态与机构尺寸**：使用 Solo 的 0.30 m 站立高度、0.2 m 大腿/小腿、髋部几何和对应默认关节角，避免用 Go2 尺寸构造错误的站立、下蹲和 IK 目标。
4. **接触与终止 link 名称**：使用 Solo 的 `Body/hip/thigh/calf/foot` 命名和足端集合，避免接触奖励、落地检测或非法接触终止指向错误刚体。
5. **姿态相关 reward 目标**：只按 Solo 几何调整站立高度、下蹲高度和空中收腿位置；Upward 的任务结构、reward 项和 PPO 参数继续继承 Go2，没有单独添加 Solo reward shaping。

## 有效控制参数改动

- 从较硬的 `Kp=20、Kd=0.5、action_scale=0.30` 调整到 `16、0.5、0.25`。Solo 质量和腿部惯量更小，原组合的起跳与落地动作过猛，容易反弹和触发落地终止；降低刚度与目标关节幅度后，真实起跳能力保留，落地质量改善。
- 保留 8 Hz EMA 动作滤波。5 Hz 对照没有证明更优，且改变响应频率会同时改变起跳时序；因此没有采用。
- 没有采用 `Kp=16、Kd=1`，该组合阻尼过大、起跳能力下降；也没有保留临时的熵、采样方差或 PPO 目标调整。

## 代码根因与有效修复

### 1. 初始下落被误判为跳跃失败

每个 episode 设计为从空中落下、站稳后再学习起跳。旧代码会在初始落地时启用重力冲击和非法接触终止；Solo 在 nominal 20 ms 下曾有 53/64 个 episode 在第 2 步被终止。Go2 也共享代码问题，但因机构、初始落地和控制响应不同，没有同程度触发，所以不能用 Go2 表现正常来否定该 bug。

修复后，非法接触只在初始站稳并经过一个控制步后启用；重力冲击只在真正离地起跳后启用。修复后的 Solo nominal 成功率为 100%，严格稳定率为 93.75%，证明它是主要训练样本删失原因之一，同时保留了“先从空中落下”的任务设计。

### 2. episode reset 状态泄漏与首步相位不一致

旧 reset 会保留上一回合的动作、接触、派生速度和部分历史状态；首次全局 reset 与后续 episode reset 还相差一个零动作控制步，造成起始观测和动作相位不一致。

修复内容包括清空动作/接触/跳跃历史，按新 root state 重算 base 速度和重力方向，重建评估端的延迟状态，并在每次物理 reset 后统一执行一个零动作步。这样消除了假双峰和对初始观测相位的异常敏感。

### 3. 物理随机参数与 buffer 不一致

刚体质量、COM 和接触属性在 actor 创建时写入 PhysX；旧 reset 又重新采样相关 buffer，却没有刷新 actor，导致观测/IMU 归一化所认为的质量与实际仿真质量不同。现改为这些 actor 级参数按 env 创建时采样并固定，4096 个 env 仍覆盖完整分布，但每个 env 内部的物理模型与观测始终一致。

同时修正 COM 语义：采样值作为 URDF nominal COM 的偏移量，而不是覆盖 nominal COM；link mass 诊断会核对采样倍率是否真实写入 PhysX。

### 4. 延迟边界语义错误

- 40 ms 以 float32 秒保存后可能略大于 0.04，旧 `ceil(latency / 20 ms)` 会变成 3 步，使所谓 40 ms 实际多出一个零动作周期。现减去数值容差后再取整，40 ms 正确映射为 2 个策略周期。
- 四元数延迟旧代码总取更老一帧，导致姿态观测比速度、关节和接触额外延迟一个周期，并在 39.9/40.0 ms 处不连续。现对每个四元数做最短半球归一化插值，使所有观测使用一致延迟。

这些修复后重新评估 Go2，Go2 固定 30/40 ms 也明显下降，说明此前“Go2 高延迟没问题、Solo 有问题”的部分结论来自共同的延迟实现错误，而不是 Solo 模型本身。

### 5. 连续随机采样没有覆盖延迟端点

标准起跳分支本来占比较低，连续 `[0, max]` 采样几乎不会精确命中最大延迟，导致固定最大延迟验收任务在训练中接近缺席。现按每回合 50% 精确 0 ms、25% 精确最大延迟、25% 区间均匀采样；再依次训练到 20、30、40 ms。20 ms 阶段严格稳定率从 74.22% 提高到 82.81%，验证了训练覆盖不足这一根因。

### 6. checkpoint 迭代编号错误

旧 runner 只每 500 轮更新内部 iteration，并在更新前保存，导致例如文件名 `model_6450.pt` 内部仍记录 6000，续训会重复或错记进度。现每轮完成后先更新 iteration，再按真实 iteration 保存。旧 checkpoint 保留旧元数据，最终后续阶段使用修复后的编号。

### 7. 验收统计不足

评估器新增真实物理离地/落地、终止原因、最终四脚接触、落地后速度/姿态/力矩振荡和逐 episode 诊断。这样可以区分“不起跳”“跳高后摔倒”“短暂四脚触地”和“稳定站立”，避免奖励或高度造成误统计。

## 域随机化与渐进训练

- 电机强度、P/D 增益：Go2 等级 `0.9–1.1`。
- link mass 倍率：Go2 等级 `0.7–1.3`。
- base 附加质量：按 Solo/Go2 nominal base 质量比例缩放为 `-0.635–+1.906 kg`。
- COM：完整缩放范围验证失败后，按用户决定暂时采用 `xyz ±0.02 m`；这是当前唯一明确小于目标 Go2 等级的物理不确定性。
- 延迟：最终为 `0–40 ms`，并显式采样零值和最大值端点。

| 阶段 | checkpoint | 固定延迟 | 跳跃成功率 | 严格稳定站立率 |
|---|---:|---:|---:|---:|
| 20 ms 端点训练 | 7550 | 20 ms | 95.31% | 82.81% |
| 30 ms 端点训练 | 8550 | 30 ms | 95.31% | 68.75% |
| 40 ms 最终验收 | 10550 | 40 ms | 95.31% | 53.91% |

40 ms 阶段的 64 回合 checkpoint 扫描中，严格稳定率从训练 1000 轮时的 48.44%，提高到 1500 轮的 59.38%、2000 轮的 64.06%；最终独立 128 回合为 53.91%。说明继续训练确有改善，但高延迟落地仍有明显方差和失败。

## 与 Go2 的修正后同协议对比

| 固定延迟 | Solo 跳跃 / 稳定 | Go2 跳跃 / 稳定 |
|---:|---:|---:|
| 20 ms | 87.50% / 67.19% | 75.00% / 57.81% |
| 30 ms | 68.75% / 51.56% | 27.34% / 16.41% |
| 40 ms | 95.31% / 53.91% | 56.25% / 28.13% |

Solo 的 20/30 ms 保留测试为 64 回合，40 ms 最终测试为 128 回合，因此小数差异不应解释为精确排名；可靠结论是 Solo 达到并超过当前 Go2 checkpoint 的同协议等级，但没有消除高延迟下的落地问题。

## 真实起跳、落地和稳定站立验收

最终 40 ms robust 共 128 回合：

- 真实物理离地 122/128（95.31%），与任务跳跃事件判定 100% 一致，无假阳性或假阴性。
- 严格稳定站立 69/128（53.91%）。
- 这 69 回合全部经过真实离地、事件落地和物理接触落地，无提前终止，自然跑完整回合，结束时四脚全部接触。
- 落地后排除 1 s 冲击减振阶段，再连续检查至少 3 s；四脚同时接触比例至少 95%，并限制线速度、角速度、姿态误差和腿部力矩变异。

因此这里的稳定成功确实是起跳后落地并四脚稳定站立，不是只达到高度、摔倒或短暂触地。

原始诊断：`outputs/quadruped-jumping-ada/logs/diagnostics/solo_m10550_endpointcurr40_final128_seed43.json`。
